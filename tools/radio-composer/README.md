# ViceBlood radio composer workbench

Development-only tooling for PR #76. It creates portable Standard MIDI File type 1 production sketches and validates their sidecar provenance/attribution manifests.

This directory is **not** a runtime audio dependency. Nothing here is imported by Phaser/gameplay code.

## Files

- `midi-workbench.js` — dependency-free MIDI writer, parser/validator, SHA-256 helper and manifest validator.
- `manifest.schema.json` — human/tool-facing JSON Schema contract for candidate sidecars.
- `smoke.js` — creates one synthetic MIDI + manifest pair and validates the pair end-to-end. It is a tooling fixture, not a radio song.
- `validate-candidate.js` — validates an existing `.mid` / `.json` pair.

The project-wide attribution rules remain authoritative in `docs/audio/RADIO_MUSIC_ATTRIBUTION.md`.

## Commands

From repository root:

```bash
npm run test:radio
npm run radio:smoke
npm run radio:validate -- phaser/assets/audio/radio-midi/<station>/<track>.mid phaser/assets/audio/radio-midi/<station>/<track>.json
```

`npm run test:unit` and therefore `npm run check:fast` also include `tests/radio-composer-workbench.test.js` automatically.

`radio:smoke` writes to an OS temporary directory by default. Pass an output directory as an extra argument when you want to inspect the files:

```bash
npm run radio:smoke -- ./tmp/radio-smoke
```

Generated temporary smoke files must not be counted as catalogue tracks.

## Minimal generation example

```js
import { buildMidiFile, inspectMidiBuffer, sha256 } from "./tools/radio-composer/midi-workbench.js";

const midi = buildMidiFile({
  title: "Working title",
  bpm: 94,
  markers: [
    { beat: 0, label: "INTRO" },
    { beat: 16, label: "A" }
  ],
  tracks: [
    {
      name: "01 Source Motif",
      channel: 0,
      program: 0,
      notes: [
        { start: 0, duration: 1, note: 60, velocity: 72 }
      ]
    },
    {
      name: "02 ViceBlood Drums",
      channel: 9,
      notes: [
        { start: 0, duration: 0.08, note: 36, velocity: 84 }
      ]
    }
  ]
});

const info = inspectMidiBuffer(midi);
console.log(info.trackNames, sha256(midi));
```

Keep source-derived melody/motif material on separately named tracks from original ViceBlood drums, bass, keys, pads, leads and FX guides.

## MIDI contract enforced by the validator

- SMF Type 1 only.
- Positive PPQ time division; default writer PPQ is 480.
- First track is a named conductor track.
- Conductor contains tempo metadata.
- Every track has an explicit name.
- Writer validates note, velocity, program and channel ranges.
- Parser rejects malformed/truncated chunks and stuck notes.
- No SysEx/proprietary state is generated by the writer.

The validator is intentionally narrow: it proves that our generated portable MIDI structure is sane. It is not intended to replace a full DAW or general-purpose MIDI parser.

## Sidecar manifest contract

Every canonical candidate gets a same-stem `.json` manifest. The required fields are documented in `manifest.schema.json` and enforced again in `validateManifest(...)` without adding a JSON-schema package dependency.

Important attribution/provenance fields include:

- `sourceWork` and `sourceComposer`;
- `sourceEditionOrCatalogue` and `sourceUrl`;
- `sourceStatus`, `sourceReuseTerms`, `sourceCheckedAt`;
- `attribution.creditMode`;
- `attribution.playerCredit` — ready-to-copy game credit text;
- `attribution.internalSourceCredit` — exact source/edition credit for repository traceability;
- `attribution.licenseOrStatus`;
- `attribution.thirdPartyAssets` — empty for the core MIDI-only workflow unless a later approved asset is introduced;
- `sha256` when the MIDI has been generated.

A candidate must not be promoted to `daw-candidate` while source or attribution information is unresolved.

## Production workflow after M1.1

For each radio candidate:

1. Verify the public-domain/licensed score/source and record its reuse terms.
2. Create the manifest attribution/provenance block **before** arrangement work.
3. Transcribe/extract only from the cleared score/source, never from a modern commercial recording.
4. Build the arrangement using 1990s station grammar from `RADIO_MUSIC_BIBLE.md`.
5. Generate the multitrack MIDI with clear source-vs-arrangement track names and section markers.
6. Write the SHA-256 into the manifest.
7. Run `radio:validate`.
8. Append progress and advance `radio-music-production-status.json` only after the bounded task is complete.

The final sound replacement, mix and mastering remain the user's DAW responsibility.
