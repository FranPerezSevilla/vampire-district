# The Black Book — gothic-punk nightbook

## Goal
Replace the functional dashboard with a coherent 1990s gothic-punk dossier that
answers five player questions. The user approved implementation and explicit
Pages publication, not another concept-only delivery.

## Authority and scope
Campaign/VampireRuntime remain the sole source of survival, relationships,
territory, business and quest facts. DomainNavigation owns presentation selection;
UIScene remains the only DOM command/input boundary. React renders the book.
Scope: ui/ views and original inline vector artwork; DomainNavigation aliases;
UIScene section shortcuts; read-only UI projection; relevant native DOM tests.

## Information architecture
1. Tonight: current errand or the existing progression recommendation; critical
   hunger warning and three contextual links. Never replace the tracked objective
   just by opening/inspecting the book.
2. City: one actual map, default hunting overlay. Ownership, reception and hunting
   remain independent. District detail separates contacts from consenting donors.
3. Network: contact files, access/trust/debt and exactly what each person offers.
   Services are in-person. Selection from another page opens the correct file.
4. Feeding: carried bags, donor agreements/readiness, stored business supply and
   a clear link to hunting rights. No invented safety, consent or territorial data.
5. Ledger: cash/debt, business operators, effective output and a secondary city
   compact/Prince progression disclosure. Incident evidence remains a separate file
   only in modes where the installed policy permits it; hidden powers and incident
   controls are omitted from the HUD/help, not re-enabled.

Old entry requests remain valid: errand/overview -> Tonight, contacts -> Network,
herd -> Feeding, resources/power -> Ledger, map -> City. Power opens its disclosure.
M opens Tonight/current errand; 1–5 select the book sections; Escape returns to play.

## Art direction
Black cloth, aged ivory, oxblood ink and restrained bruised violet; photocopy
halftone, taped task sheets, cut-paper index tabs, contact prints and receipts.
Serif display + condensed headings + typewriter labels, with plain readable body
text. Ornament never carries a rule alone and never blocks pointer events.
Original inline SVG identity prints and CSS textures: no new download, external
font, image service, animation loop, backdrop blur or WebGL layer.

## Acceptance
- Five clearly named destinations, one dominant current task, contextual links.
- Blood sources together; permits are not consent and reception is not a permit.
- Actual campaign commands, queued transactions, map tracking and focus survive.
- The installed production surface policy and actual Phaser injection are tested.
- Main title, packed boot, camera handoff, audio, simulation and saves untouched.
- Responsive full-viewport book; stacked short/narrow layouts and scrolling;
  keyboard control, visible focus, text status alongside colour, reduced motion.
- Native and compiled-output checks; report browser visual acceptance separately.

## Validation / delivery
Run focused native/React tests, full check:fast, affected plan (retain the user's
browser exclusion), build, package verification and compiled-module smoke. Publish
only the exact green source plus CI-produced static files, no force push or PR
merge. Verify public provenance and bytes through the existing bounded HTTP job.
Native/jsdom/CSS-contract checks are not browser pixel/FPS validation.

The compiled-module smoke exercises all five new chapters, renders the actual
React DOM from production bytes for both hosted entry points, and checks that
inspection does not replace the tracked objective and closing releases pause.
The installed-policy DOM suite checks cross-file links, numeric keys, hidden
capabilities, carried-blood queuing, errand prominence and donor consent.
No title artwork, viewport root, audio, boot pack or gameplay/save files changed.
